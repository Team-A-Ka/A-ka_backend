## 🐛 발견·해결한 트러블슈팅 (포트폴리오 §9 보강 후보)

### ✅ 해결 — Celery 5.x errback 호출 규약 회귀 (`handle_pipeline_failure_task`)

**상황**
포트폴리오 §9 사례 1에서 *"`(self, video_id, user_id, request, exc, traceback)`으로 시그니처 확장해서 해결"*로 정리한 트러블슈팅이 **Celery 5.x 업그레이드 이후 다시 발생**.

**증상**
```
TypeError: handle_pipeline_failure_task() missing 2 required positional arguments: 'exc' and 'traceback'
```
파이프라인 실패 시 워커가 `--pool=solo`에서 죽음. 좀비 PENDING 행 누적.

**원인**
Celery `backends/base.py`의 `_call_task_errbacks`가 errback 함수 시그니처를 검사:
- `arguments(fn.__header__).args[1:3] == ('exc', 'traceback')` 이면 → **레거시 모드** (exc, traceback 자동 주입)
- 아니면 → **모던 모드** (task_id 1개만 주입)

기존 시그니처는 `(self, video_id, user_id, ...)`라 `args[1:3]=('video_id','user_id')`로 모던 모드 분류 → task_id 1개만 들어와 TypeError.

**해결** (`app/tasks/knowledge_tasks.py:57-78`)
```python
@shared_task(bind=True, name="knowledge.handle_failure")
def handle_pipeline_failure_task(self, exc, traceback, video_id: str, user_id: int):
    # args[1:3] = ('exc', 'traceback') → Celery 레거시 모드 발화
    task_id = self.request.id if self.request else None
    ...
```
`.on_error(handle_pipeline_failure_task.s(video_id, user_id))`의 partial 인자는 뒤에 추가되므로 최종 호출은 `handle(exc, traceback, video_id, user_id)`.

**결과**
파이프라인 실패 시 워커 생존 + DB FAILED 마킹 + 사용자 안내 메일 발송 모두 정상.

**교훈**
프레임워크 업그레이드 시 errback/callback 같은 *"인자 주입 규약"* 항목은 메이저 버전 차이에서 자주 깨짐. 시그니처를 코드 코멘트에 명시하지 않으면 회귀 잡기 어려움.

### ⏸ 미해결 (다음 세션) — 자막 비활성 영상에서 STT fallback 미발화

**위치**: `app/services/youtube_service.py:133-183`

**증상**
`Subtitles are disabled for this video`인 영상은 outer `except`가 잡아서 *"Error fetching transcript: …"* 문자열을 리턴 → 파이프라인 raise. Whisper STT fallback(`_run_stt_process`)은 inner try 안에만 있어 발화 안 함.

**예시 영상**: `https://youtu.be/cC5Yub8P0aQ` (네 시연 영상)

**1줄 fix 안**:
```python
except Exception as e:
    # 자막 트랙 자체가 없거나 사용 불가일 때도 STT fallback으로 진입
    return self._run_stt_process(video_id)
```
단, Whisper는 ffmpeg 필요 + CPU·디스크 자원 큼. 본격 시도 전에 자원 확인 권장.

### ⏸ 미해결 (다음 세션) — Gemini 2.0 deprecation 경험

**증상 흐름**:
1. 처음 `GEMINI_MODEL=gemini-2.0-flash` + free tier → "Quota exceeded, limit:**0**" (오해 유도)
2. paid tier 1 업그레이드 → 동일 모델 호출 시 **404 NOT_FOUND** ("This model is no longer available")
3. free tier에서 "limit:0"으로 위장돼있던 게 실은 모델 폐기

**해결**: `GEMINI_MODEL=gemini-2.5-flash-lite`로 핀. flash-lite는 thinking off 기본 + paid 단가 $0.10/$0.40/1M로 가장 저렴.

**포트폴리오 가치**
> *"무료 티어 'limit:0' 에러가 실은 모델 deprecation을 위장하던 케이스. paid tier 전환 후 진짜 에러(404)가 드러나서 발견. 모델 핀 + 신뢰 가능한 단가 채널로 회피."*
