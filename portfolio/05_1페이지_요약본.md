## 한 줄 정체성

카카오톡 단일 자연어 채널에서 사용자 의도를 LLM으로 분류하고, LangGraph 기반 RAG 파이프라인으로 영상 콘텐츠를 자동 요약·검색 가능하게 만드는 AI 백엔드 시스템.

---

## 프로젝트 한 줄

카톡으로 유튜브 영상을 보내면 AI가 자동으로 요약·분류·검색까지 처리해 노션에 아카이브해주는 개인 영상 라이브러리 서비스.

---

## 본인 담당 (4인 팀 중)

- AI 라우터 — 의도 분류와 4갈래 분기
- LangGraph 2개 그래프 — Intelligence와 SEARCH RAG
- 임베딩 파이프라인과 pgvector 저장
- RAG 검색 답변 생성 — 할루시네이션 4중 방어
- 유사 영상 추천 — 영상 단위 dedup
- SAVE_ONLY 메타데이터 저장 로직
- 트러블슈팅 — Celery `.on_error()` 인자 자동 주입 이슈 진단·해결

---

## 아키텍처 한 줄 요약

```
카톡 → 웹훅 즉시 ACK → Redis → Celery 워커 → AI 라우터 4갈래 분기
  → Intelligence 그래프 (요약·임베딩·Overview) → 노션 페이지
  또는 SEARCH RAG 그래프 (벡터 검색·LLM 답변) → SMTP 메일
```

---

## 핵심 성과 (정량)

| 지표 | 값 |
|---|---|
| 카카오톡 5초 응답률 | 100% |
| 영상 1편 자동 요약 시간 | 약 30~120초 (추정) |
| 검색 응답 시간 | 약 5~10초 (추정) |
| SAVE_ONLY 비용 절감 | LLM 호출 0회 (UPLOAD 대비 토큰 비용 100% 절감) |
| 할루시네이션 방어 | 4중 (임계값, 시스템 프롬프트, 출처 강제, 빈 결과 분기) |
| 트러블슈팅 해결 | 침묵 실패 1건 (Celery `.on_error()`) |

---

## 핵심 설계 결정

1. AI 라우터를 LLM 구조화 출력 기반으로 설계 — URL과 키워드 유무에 따라 결과 형식이 갈리는 미세한 자연어 의도까지 분류
2. 원본 자막 대신 요약본을 임베딩 — 노이즈 제거로 검색 변별력 확보
3. 거리 임계값 필터링 (RAG 0.7 / 유사 영상 0.8) — 할루시네이션 사전 방어
4. 채널 분리 정책 — 영상 요약은 노션, 검색 결과는 메일, 카톡은 ACK만으로 챗봇 발송 비용 0과 영구 보관성 동시 확보
5. FIND_SIMILAR을 UPLOAD 파이프라인 재사용 + `include_similar=True` 플래그로 통합 — 코드 중복 제거

## 핵심 기술 스택

`LangGraph` · `FastAPI` · `Celery + Redis` · `PostgreSQL + pgvector` · `OpenAI text-embedding-3-small` · `Docker Compose`

---

## 트러블슈팅 한 줄

3단계 Celery chain에 등록한 `.on_error()` 핸들러가 호출되지 않은 채 DB가 PROCESSING 상태에서 멈추는 침묵 실패가 발생했습니다. 워커 로그와 Celery 공식 문서를 정독한 결과 `.on_error()` 콜백이 실패 태스크의 `(request, exc, traceback)` 3개 인자를 자동 주입한다는 사실을 파악했고, 시그니처를 확장해 파이프라인 실패 시 DB FAILED 마킹과 사용자 안내 메일이 정상 동작하도록 해결했습니다.

---

## 회고

잘한 결정으로는 LangGraph 도입(조건부 분기와 노드별 디버깅, LangSmith 트레이싱 동시 확보), 요약본 임베딩(자막 노이즈 제거로 검색 정확도 확보), 채널 분리 정책(챗봇 비용 0과 영구 보관성 동시 확보)이 있습니다.

다시 한다면 SEARCH 그래프를 처음부터 async로 설계해 동시성을 확보하고, 영상 단위 캐시를 추가해 동일 영상 처리 비용을 줄이며, LangSmith 평가 데이터셋을 초기에 구축해 의도 분류 정확도를 자동 회귀 테스트할 수 있도록 했을 것입니다.
