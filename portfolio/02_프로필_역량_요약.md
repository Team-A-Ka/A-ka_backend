## 3. Executive Summary — 핵심 요약 (결과 · 운영 · 회고)

> 잡코디 가이드의 *"결과·운영·회고 3요소"* 구조.

### 결과

A-KA는 카카오톡 단일 채널에서 4가지 사용자 의도(영상 요약 / 저장만 / 유사 영상 / 자연어 검색)를 자동 분류해 처리하는 AI 백엔드 시스템입니다. 본인은 AI 라우터, LangGraph 2개 그래프, RAG 검색 답변 생성, 유사 영상 추천 영역을 설계·구현했습니다.

- 카카오톡 5초 응답 룰 100% 준수 — 즉시 ACK + Celery 백그라운드 위임 패턴
- 할루시네이션 4중 방어 설계 — 임계값, 시스템 프롬프트, 출처 강제, 빈 결과 분기
- LLM 비용 최적화 — SAVE_ONLY 분기로 *"저장만"* 의도일 때 LLM 호출 0회 (UPLOAD 대비 토큰 비용 100% 절감)
- 결과 채널 분리 정책 — 카톡은 ACK만, 노션은 영상 요약, 메일은 검색 결과로 분리해 챗봇 발송 비용 0과 영구 보관성을 동시 확보

### 운영

운영 안정성을 위해 다음 메커니즘을 적용했습니다.

- 3단계 Celery chain (collect_and_chunk → run_intelligence → publish) 위에 통합 `.on_error()` 핸들러를 걸어 어느 단계에서 실패하든 한 곳에서 처리
- 실패가 발생하면 DB status를 FAILED로 마킹하고 사용자에게 안내 메일을 자동 발송
- `check_duplicate_hit_count`로 중복 영상은 hit_count만 증가시키고 LLM 재호출을 방지
- summary가 비어있는 SAVE_ONLY 레코드를 발견하면 풀 파이프라인으로 자동 승격

운영 중 만난 대표 트러블슈팅은 Celery `.on_error()` 콜백이 호출되지 않는 침묵 실패였습니다. 콜백이 실패 태스크의 `(request, exc, traceback)` 3개 인자를 자동 주입한다는 사실을 인지하지 못한 채 핸들러를 등록한 결과, 인자 개수 불일치로 핸들러가 즉시 죽고 DB는 PROCESSING 상태에 멈춰 있었습니다. 워커 로그 정독과 공식 문서 재검토로 원인을 파악한 뒤 시그니처를 확장해 해결했습니다.

### 회고

LangGraph 도입은 조건부 분기, 노드별 디버깅, LangSmith 트레이싱을 동시에 확보할 수 있었던 결정이었습니다. 요약본을 임베딩한 선택은 자막 노이즈 문제를 초기에 인식하고 잡아낸 덕분에 검색 변별력을 확보하는 데 기여했습니다. 카톡 챗봇이 아닌 노션과 메일로 결과를 분리한 채널 정책은 발송 비용과 영구 보관성을 동시에 챙길 수 있었던 결정이었습니다.

다시 한다면 SEARCH 그래프를 처음부터 `ainvoke`와 async session으로 설계해 동시성을 확보했을 것입니다. 영상 단위 캐시도 미리 넣었다면 같은 영상이 여러 사용자에게 들어왔을 때 자막 추출과 요약을 한 번만 수행할 수 있었을 것입니다. LangSmith 평가 데이터셋도 초기에 구축했다면 의도 분류 정확도를 자동으로 회귀 테스트할 수 있었을 것입니다.

다음 단계로는 데이터 규모가 커지는 시점에 Matryoshka 차원 축소와 HNSW 인덱스 튜닝을 검토할 계획입니다. 콘텐츠 타입도 영상에서 블로그와 팟캐스트로 확장해 *"개인 지식 저장소"* 라는 정체성을 강화할 수 있습니다.
