## 3. Executive Summary — 핵심 요약 (결과 · 운영 · 회고)

> 잡코디 가이드의 *"결과·운영·회고 3요소"* 구조.

### 🎯 결과

A-KA는 카카오톡 단일 채널에서 4가지 사용자 의도(영상 요약/저장만/유사 영상/자연어 검색)를 자동 분류해 처리하는 AI 백엔드 시스템입니다. 본인은 **AI 라우터 + LangGraph 2개 그래프 + RAG 검색 답변 생성 + 유사 영상 추천** 영역을 설계·구현했습니다.

핵심 성과 4가지:
1. **카카오톡 5초 응답 룰 100% 준수** — 즉시 ACK + Celery 백그라운드 위임 패턴
2. **할루시네이션 4중 방어** 설계 — 임계값·시스템 프롬프트·출처 강제·빈결과 분기
3. **LLM 비용 최적화** — SAVE_ONLY 분기로 의도가 *"저장만"* 인 경우 LLM 호출 0회 (UPLOAD 대비 100% 토큰 비용 절감)
4. **결과 채널 분리 정책** — 카톡 ACK / 노션 페이지 / SMTP 메일을 용도별 분리해 챗봇 발송 비용 0 + 영구 보관성 확보

### ⚙️ 운영

운영 안정성을 위해 다음 메커니즘을 설계:

- **3단계 Celery chain** (collect_and_chunk → run_intelligence → publish) + **`.on_error()` 통합 핸들러**로 어느 단계든 실패하면 단일 핸들러에서 처리
- **실패 시 자동 동작**: DB status FAILED 마킹 + 사용자에게 안내 메일 자동 발송
- **중복 영상 처리 분기**: `check_duplicate_hit_count`로 hit_count++만 하고 LLM 재호출 방지
- **SAVE_ONLY → UPLOAD 자동 업그레이드**: summary 비어있는 레코드 발견 시 풀 파이프라인 승격

운영 중 발견한 **트러블슈팅 사례**:
Celery `.on_error()` 콜백이 실패한 태스크의 `(request, exc, traceback)` 3개 인자를 자동 주입한다는 사실을 모른 채 핸들러 시그니처를 등록 → 인자 개수 불일치로 핸들러가 즉시 죽고 DB는 PROCESSING에 멈춤 → 사용자에겐 아무 안내도 안 가는 **침묵 실패** 발생. Celery 워커 로그 정독 + 공식 문서 재검토로 원인 파악, 시그니처 확장으로 해결.

### 🔄 회고

**잘한 결정 3가지:**
- LangGraph 도입으로 조건부 분기·노드별 디버깅·LangSmith 트레이싱 동시 확보
- 원본 자막이 아닌 **요약본을 임베딩**해 검색 변별력 확보
- 카톡 챗봇이 아닌 **노션/메일 채널 분리**로 발송 비용 0 + 영구 보관

**다시 한다면:**
- SEARCH 그래프를 처음부터 `ainvoke` + async session으로 설계해 동시성 확보
- 영상 단위 캐시 추가 (같은 영상 두 사용자가 보내면 자막 추출 1회만)
- LangSmith 평가 데이터셋을 처음부터 만들어 의도 분류 정확도 자동 회귀 테스트

**다음 가설:**
- 데이터 규모 돌파 시 Matryoshka 차원 축소(512) + HNSW 인덱스 튜닝 검토
- 영상 외 콘텐츠(블로그·팟캐스트)로 확장
- 사용자별 영상 캐시 + 글로벌 캐시 분리로 사생활 격리 + 비용 절감 동시 달성
