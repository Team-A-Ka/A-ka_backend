## 🟡 +0.5: KPI 정량화 (가장 쉬움)

### 현재 상태
대부분 "추정값" 표기. 실제 측정값이 없음.

### 만점 가는 방법

**Claude Code 환경에서 다음 KPI를 실측:**

| 측정 항목 | 어떻게 | 예상 결과 |
|---|---|---|
| **UPLOAD 파이프라인 총 시간** | `time` + Celery flower 로그 | 영상 길이별 30~150초 |
| **SEARCH RAG 응답 시간** | API 호출 wrapper로 측정 | 5~10초 |
| **청크 요약 병렬 효과** | ThreadPool ON/OFF 두 번 실행 | 약 8~10배 단축 |
| **임베딩 배치 vs 개별 호출** | 토큰 사용량 + API 응답 시간 | 호출 횟수 N→1배 |
| **LLM 호출 횟수/영상** | LangSmith 로그 | 청크 수 + Overview 1 + 카테고리 1 |
| **할루시네이션 발생률** | 평가셋 50개 케이스 | 정량 비율 |

**Claude Code에서 던질 프롬프트:**

```
A-KA 포트폴리오용 KPI를 실측해줘.

1. UPLOAD 흐름:
   - 영상 3개(짧음 5분 / 중간 20분 / 김 60분) 골라
   - 각각 collect_and_chunk → run_intelligence → publish 시간 측정
   - LangSmith 로그도 같이 캡처

2. SEARCH RAG:
   - 질문 5개 준비
   - search_and_answer 호출 시간 평균/최대/최소
   - 청크 검색만 vs 전체(임베딩+검색+답변) 분리

3. 병렬 처리 효과:
   - summarize_each_chunk를 max_workers=1 vs max_workers=10으로 비교

결과를 표로 정리해서 portfolio/KPI_측정결과.md에 저장.
```

→ 결과를 `01_대표프로젝트_AKA.md`의 "8. 결과/임팩트" 섹션에 반영.

## 🟡 +0.5: 검증 / 평가셋 / 에러 분석

### 현재 상태
임계값 튜닝·할루시네이션 4중 방어는 정성적으로 설명. 정량 평가셋이 없음.

### 만점 가는 방법

**의도 분류 평가셋 만들기 (30분 작업):**

`portfolio/intent_eval_set.md` 파일 만들고 다음 형식으로 50개 케이스 작성:

```markdown
# 의도 분류 평가셋

| # | 입력 | 정답 | 분류 결과 | 일치 |
|---|---|---|---|---|
| 1 | "https://youtu.be/abc" | UPLOAD | UPLOAD | ✅ |
| 2 | "https://youtu.be/abc 비슷한 영상" | FIND_SIMILAR | FIND_SIMILAR | ✅ |
| 3 | "https://youtu.be/abc 나중에 볼게" | SAVE_ONLY | SAVE_ONLY | ✅ |
| 4 | "와인이 두통을 유발하는 이유" | SEARCH | SEARCH | ✅ |
| 5 | "저장만이라는 단어 쓰지 마" | UNKNOWN | UNKNOWN | ✅ |
... (50개)

## 정확도
- 정답률: 47/50 = 94%
- 오답 분류:
  - #12: SEARCH로 분류해야 했는데 UNKNOWN (이유: ...)
  - #28: SAVE_ONLY로 분류해야 했는데 UPLOAD (이유: ...)
  - #41: FIND_SIMILAR로 분류해야 했는데 SEARCH (이유: ...)
```

**RAG 답변 품질 평가셋 (선택, 20분):**

질문 10개 + 정답 + 실제 LLM 답변 + 출처 URL 정확성 매칭.

→ 결과를 `01_대표프로젝트_AKA.md`의 "7. 실험/검증" 섹션에 반영.

**Claude Code 프롬프트:**
```
의도 분류 평가셋 50개 만들고 정확도 측정해줘.
각 인텐트(UPLOAD/SAVE_ONLY/FIND_SIMILAR/SEARCH/UNKNOWN)별로 10개씩,
경계 케이스(부정문, 인용, 인젝션 시도)도 포함.
analyze_intent() 함수에 돌려서 정답 일치율 + 오답 분석.
```

## 🟡 +0.5: 스토리화 (문제→결정→검증→결과)

### 현재 상태
11항목으로 흐름은 있지만, 각 섹션 시작 부분이 *"무엇을 했다"* 식 서술. *"왜 그 결정을 했고 어떻게 검증했는지"* 흐름이 약간 약함.

### 만점 가는 방법

**3가지 작업:**

#### A. 각 챕터 시작에 "문제 → 결정" 한 문장 추가

예시 - 현재 *"5. 접근 방법"* 도입부:
> "벡터 DB 선택지 비교..."

수정 후:
> *"의미 기반 검색을 위해 벡터 DB가 필요한데, **검색 정확도 + 운영 단순성 + 비용** 세 가지를 모두 최적화하려면 어떤 선택지를 골라야 하는가? 라는 질문에서 시작해 다음과 같이 비교했습니다."*

→ **"질문"으로 시작하는 흐름**이 채용자 입장에서 잘 읽힘.

#### B. 트러블슈팅 케이스 1~2개 추가 발굴

현재는 Celery `.on_error()` 1개. 2~3개면 더 풍부.

추가 가능한 트러블슈팅 후보:
- **LLM 응답이 가끔 JSON 형식 안 맞아서 구조화 출력 실패** → `with_structured_output` + 재시도 3회로 대응
- **카테고리가 *"백엔드", "서버 개발"* 같이 분산** → `resolve_category_name`으로 우산 정규화
- **유사 영상 결과에 같은 영상 청크 여러 개 나옴** → 영상 단위 dedup 그루핑

→ 위 중 1~2개를 짧게(반페이지) `01_대표프로젝트_AKA.md`의 "9. 운영/확장"에 추가.

#### C. 외부 피드백 받아서 문장 다듬기

동료/멘토에게 PDF 보여주고:
- *"30초 안에 무슨 서비스인지 이해돼?"*
- *"본인이 뭘 했는지 명확해?"*
- *"각 결정의 이유가 납득가?"*

받은 피드백을 그대로 반영.

## 🎁 보너스: 17점 이상 가는 방법 (가이드 만점 초과)

가이드는 16점이 최대지만, 실제 면접에서 *"와 이 사람 진짜 잘했네"* 인상을 주는 추가 자산:

1. **기술 블로그 글 1편** — Celery `.on_error()` 트러블슈팅이 가장 임팩트 큼 (희소 사례)
2. **LangSmith 트레이싱 스크린샷** — RAG 답변의 토큰 사용량·노드 흐름 시각화
3. **시연 영상 2종** — 현재 1분 32초 풀버전 + 30초 압축본 (면접 빠르게 보여주기용)
4. **벤치마크 비교 그래프** — pgvector vs Pinecone 응답 시간 직접 측정 (가능하면)
5. **A/B 테스트 결과** — 요약본 임베딩 vs 원본 자막 임베딩 검색 정확도 비교

이 중 1~2개만 있어도 *"평균 신입과 다르네"* 인상.
